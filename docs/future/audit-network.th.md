# เครือข่ายตรวจสอบแบบเปิด: ใครก็ตรวจได้ ใครก็ถูกตรวจได้ ใบรับรองผูกกับโค้ด

ใช้บนเทสต์เน็ตเท่านั้น ไม่มีเงินจริงเข้าหรือออก และส่วนนี้ยังไม่ผ่านการตรวจสอบจากบริษัทภายนอก

ZETAPHY มี**แพลตฟอร์มตรวจสอบสัญญาแบบเปิด** ใครก็ขอให้ตรวจสัญญาได้ ไม่ว่าจะเป็นสัญญาของ ZETAPHY เองหรือสัญญาบนเชนอื่นที่ Neuro อ่านได้ ใครที่วางเงินประกันก็เป็นผู้ตรวจได้ คณะกรรมการที่วางเงินประกันเป็นผู้ตัดสินทุกข้อค้นพบ และรันเนอร์สามตัวรันเครื่องมืออัตโนมัติบนโค้ดตัวจริง โค้ดที่ผ่าน**ทุกข้อ**จึงได้ใบรับรองบนเชน ซึ่งผูกกับแฮชของโค้ดนั้น ZETAPHY ตรวจโปรเจกต์อื่น และโปรเจกต์อื่นก็ตรวจ ZETAPHY ได้ภายใต้กติกาเดียวกัน ไม่มีคีย์เจ้าของ: governance คือ `ZetaphyTimelock` และทุกพารามิเตอร์มีขอบเขตตายตัว

## ขั้นตอน

1. **ขอตรวจ**: ผู้สนับสนุนระบุ chainId, ที่อยู่, codeHash, แฮชซอร์ส, ระดับขอบเขต, ระยะแข่งขัน และจำนวนผู้ตรวจขั้นต่ำ แล้ววางเงิน (เงินรางวัล + ค่าธรรมเนียม) บน ZETAPHY codeHash ต้องเท่ากับ EXTCODEHASH ของที่อยู่นั้นในขณะนั้น
2. **ช่วงแข่งขัน** (อย่างน้อย `minContest` บวก 1 สัปดาห์ต่อระดับ):
   - ผู้ตรวจคอมมิตรายงานการเข้าร่วม และข้อค้นพบ (เป็นแฮชของ ข้อค้นพบ + ความรุนแรง + แฮช PoC + ผู้ตรวจ + salt + คำขอ)
   - รันเนอร์คอมมิตแฮชของผลรวม (resultHash, จำนวนวิกฤต+สูง, invariant ที่ล้มเหลว/ไม่ได้รัน, คะแนน mutation)
3. **ช่วงเปิดเผย**: ทุกคนเปิดเผยหลังการแข่งขันจบ จึงไม่มีใครลอกได้ และรันเนอร์ต้องตรงกัน 2 ใน 3
4. **ช่วงตัดสิน**: กรรมการโหวตเรื่องเหล่านี้
   - แต่ละข้อค้นพบ: จริง พร้อมความรุนแรงและกลุ่มที่ซ้ำ หรือไม่จริง
   - รายงานการเข้าร่วม: รับ หรือปฏิเสธ
   - คำประกาศ "invariant ไม่เกี่ยวข้อง": รับ หรือไม่รับ
   - การแก้ที่ยกมาจากเวอร์ชันก่อน: แก้แล้ว หรือยัง
5. **ช่วงอุทธรณ์**: ใครก็อุทธรณ์คำตัดสินได้ (ต้องวางเงินประกัน) แล้ว governance เป็นผู้ตัดสิน ถ้าไม่ตัดสินภายใน `appealTimeout` คำตัดสินเดิมคงอยู่
6. **สรุปยอดและจ่ายเงิน** (ผู้รับต้องดึงเงินเอง) จากนั้นจึงเรียก `certify` ได้ และจะสำเร็จก็ต่อเมื่อผ่านทุกกติกาด้านล่าง

**การแก้คือคำขอใหม่**: โค้ดใหม่มี codeHash ใหม่ คำขอใหม่ต้องอ้างคำขอเดิม (`prev`) ข้อค้นพบระดับวิกฤต/สูงที่จริงของเวอร์ชันเดิมจะถูก**ยกมา** และกรรมการต้องยืนยันว่าแก้แล้วทีละข้อ เวอร์ชันใหม่ต้องผ่านกระบวนการทั้งหมดอีกครั้ง

## ใบรับรองต้องมีอะไรบ้าง (ตรงตามโค้ด)

`AuditCertificate.certify(id)` สำเร็จเมื่อ `check(id) == 0` เท่านั้น คือทุกข้อต่อไปนี้ต้องจริง:

1. **สรุปยอดแล้ว**: ช่วงแข่งขัน เปิดเผย ตัดสิน และอุทธรณ์จบหมด และไม่มีการอุทธรณ์ค้าง
2. **ชั้นอัตโนมัติตรงกัน** (2 ใน 3) และ**ไม่มีปัญหาวิกฤต/สูงที่เปิดอยู่** สถานะ "accepted" ยังนับเป็นเปิดอยู่ มีแค่ `fixed` หรือ `false-positive` เท่านั้นที่ไม่นับ
3. **Invariant**: ไม่มีชุดไหนล้มเหลว และทุกชุดได้รัน หรือผู้สนับสนุนประกาศว่าไม่เกี่ยวข้องและกรรมการรับคำประกาศนั้น
4. **การแข่งขัน**: นานพอตามขั้นต่ำ (ไม่ต่ำกว่า 3 วัน) และมีผู้ตรวจที่วางเงินประกันอย่างน้อย `minAuditors` คนที่เปิดเผยรายงานซึ่งไม่ถูกปฏิเสธ
5. **ข้อค้นพบ**: ไม่มีข้อวิกฤต/สูงที่จริง ไม่มีข้อที่ยังไม่ตัดสิน และทุกข้อที่ยกมาถูกยืนยันว่าแก้แล้ว
6. **โค้ดและเงิน**: บน ZETAPHY ที่อยู่นั้นยังมีโค้ดที่ตรวจตรงตัว แฮชโค้ดนี้ไม่เคยถูกเพิกถอน และผู้สนับสนุนยังไม่ได้ถอนเงินสำรอง

**ระดับ**:
- **ทอง**: ผู้ตรวจ ≥ 8 คน แข่งขัน ≥ 21 วัน และ mutation ≥ 85%
- **เงิน**: ผู้ตรวจ ≥ 5 คน แข่งขัน ≥ 14 วัน และ mutation ≥ 70%
- **ทองแดง**: ผ่านทุกกติกาแต่ไม่ถึงระดับเงิน

เกณฑ์ทั้งหมดนี้ governance ปรับได้ภายในขอบเขต

**อายุ**: ใบรับรองหมดอายุตาม `validity` (ค่าเริ่มต้น 180 วัน ปรับได้ในช่วง 30..365 วัน) `isCertified(chainId, address)` จะเป็นเท็จทันทีในกรณีเหล่านี้:
- ใบรับรองหมดอายุ
- ใบรับรองถูกเพิกถอน
- แฮชโค้ดถูกเพิกถอน
- บน ZETAPHY EXTCODEHASH **ปัจจุบัน** ของที่อยู่ไม่ตรงกับที่รับรอง (ดีพลอยใหม่หรือโค้ดเปลี่ยน)

**การเพิกถอน**: หลังออกใบรับรอง ยังส่งข้อค้นพบได้จนกว่าใบรับรองจะหมดอายุ ถ้าข้อค้นพบระดับวิกฤต/สูงถูกตัดสินว่าจริง ใบรับรองจะถูกเพิกถอน**ทันที** และแฮชโค้ดนั้นจะถูกเพิกถอนทุกที่ จึงรับรองโค้ดเดิมซ้ำไม่ได้อีก

## ใบรับรองหมายถึงอะไร และไม่ได้หมายถึงอะไร

ใบรับรองบอกว่า **"โค้ดนี้ตรงตัว (แฮช X) ผ่านกระบวนการตรวจสอบแบบเปิดของ ZETAPHY ในวันที่ Y"** คือในวันนั้น:
- เครื่องมืออัตโนมัติไม่พบปัญหาวิกฤต/สูงที่เปิดอยู่
- invariant ผ่าน หรือได้รับการยอมรับว่าไม่เกี่ยวข้อง
- มีผู้ตรวจที่วางเงินประกันอย่างน้อย M คนดูโค้ดในการแข่งขันสาธารณะอย่างน้อย N วัน
- ทุกข้อค้นพบผ่านการตัดสินและมีช่วงอุทธรณ์ และไม่มีข้อวิกฤต/สูงที่ยังยืนอยู่

ใบรับรอง**ไม่ใช่**การรับประกันว่าโค้ดปลอดภัย ไม่ได้ประเมินทีม เศรษฐศาสตร์ oracle หรือคีย์แอดมินรอบสัญญา และไม่ใช่ประกันภัย ผู้ตรวจพลาดได้ เครื่องมือมีจุดบอด และกรรมการก็ผิดได้ ใบรับรองครอบคลุม**เฉพาะโค้ด และเฉพาะแฮชนั้น**

**Proxy**: ไบต์โค้ดของ EIP-1967 proxy ไม่เปลี่ยนเมื่ออัปเกรด สิ่งที่เปลี่ยนคือ implementation ให้รับรอง implementation ด้วย ป้ายใน explorer อ่านช่อง implementation ของ EIP-1967 และจะแสดงว่ารับรองก็ต่อเมื่อทั้ง proxy และ implementation ปัจจุบันได้รับรอง ส่วนสัญญาที่เรียกใช้บนเชนต้องเรียก `isCertified(implementation)` เอง

## ความเข้มงวด (และการทดสอบ)

แต่ละข้อมีการทดสอบใน `zetaphy-network/test/auditnet.test.js`:
- ลอกข้อค้นพบไม่ได้ก่อนเปิดเผย
- มีข้อสูงที่จริงค้างอยู่ก็ไม่ได้ใบรับรอง
- ผู้ตรวจน้อยไป ช่วงแข่งขันสั้นไป หรือช่วงอุทธรณ์ยังไม่จบ ก็ไม่ได้ใบรับรอง
- ชั้นอัตโนมัติต้องตรงกัน
- ข้อวิกฤตที่พบภายหลังทำให้ใบรับรองถูกเพิกถอน
- ใบรับรองใช้ไม่ได้เมื่อโค้ดเปลี่ยน
- การยึดเงินประกันและการคืนเมื่อชนะอุทธรณ์
- กรรมการฝั่งข้างน้อยฮั้วกันตัดสินอะไรไม่ได้
- การเล่นซ้ำ (replay)
- reentrancy ตอนจ่ายเงิน
- การหมดอายุ
- พารามิเตอร์มีขอบเขต และมีแค่ governance ที่ปรับได้

นอกจากนี้มีการทดสอบแบบครบวงจรที่ส่งธุรกรรมจริงผ่าน CLI (`test/auditnet-e2e.test.js`) จนถึงตอนที่ explorer และ hub อ่านใบรับรอง

## ชั้นอัตโนมัติและ AI

`zetaphy audit run <id>` ทำงานดังนี้:

1. ดึงโค้ดและตรวจว่าตรงกับ codeHash ถ้า Sourcify มีซอร์สที่ยืนยันแล้วก็ดึงมาด้วย (ฟรี)
2. รัน `node audit/report.js --json <outdir>` ผ่านตัวต่อที่ตรวจรูปแบบเข้มงวด (รูปแบบอยู่ใน `test/fixtures/audit-report.json`)
3. รันกฎของ Neuro บนโค้ดตัวจริง
4. คำนวณแฮชของผลแบบมาตรฐาน แล้วคอมมิตและเปิดเผย

**LLM ไม่บังคับ**: ทำงานเฉพาะเมื่อเจ้าของรันเนอร์ตั้งค่าโมเดลไว้เอง ผลของ AI เป็นแค่ความเห็นและ**ไม่อยู่ในแฮช** ถ้าจะใช้ ต้องส่งเป็นข้อค้นพบปกติให้กรรมการตัดสิน AI อย่างเดียวรับรองหรือทำให้สัญญาตกไม่ได้

## เศรษฐศาสตร์ (ค่าเริ่มต้น ทุกค่ามีขอบเขต)

- **ค่าธรรมเนียม**: 10% ของเงินที่วาง ครึ่งหนึ่งให้รันเนอร์ อีกครึ่งให้กรรมการที่โหวตตรงกับคำตัดสิน
- **เงินรางวัล**: 10% แบ่งให้รายงานการเข้าร่วม ส่วนที่เหลือแบ่งตามน้ำหนักความรุนแรง (ข้อมูล 0, ต่ำ 1, กลาง 3, สูง 10, วิกฤต 30) ข้อค้นพบที่ซ้ำกันแบ่งส่วนของกลุ่ม
- **เงินประกันผู้ตรวจ**: 10 ZTPHY ข้อค้นพบที่ไม่จริงหรือรายงานที่ถูกปฏิเสธเสีย 20% เงินที่ยึดจะถูกพักไว้จนอุทธรณ์จบ แล้วจึงให้ผู้สนับสนุน
- **กรรมการ**: เงินประกัน 100 ZTPHY คะแนนชื่อเสียงขั้นต่ำ 500 และองค์ประชุม 3 เสียงพร้อมเสียงข้างมากของกรรมการที่ใช้งานอยู่
- **อุทธรณ์**: วางเงินประกัน 10 ZTPHY ถ้าแพ้ เงินเข้าคลัง ถ้าชนะหรือหมดเวลาได้คืน
- **เงินรางวัลหลังออกใบรับรอง**: คือเงินรางวัลที่เหลือ วิกฤตได้ทั้งหมด สูงได้ครึ่งหนึ่ง

ผลทั้งหมดถูกบันทึกลง `WorkerReputation`

## ข้ามเชน

ใบรับรองของสัญญาบนเชนอื่นถูกบันทึกด้วย chainId และ codeHash ของเชนนั้น `NeuroOracleSender.pushCertificate` ส่งใบรับรองผ่าน Hyperlane และ `NeuroOracle.isCertified` บนเชนปลายทางจะตรวจ EXTCODEHASH ในเชนนั้นเอง ถ้าจะเปิดใช้กับ oracle ที่ดีพลอยไปแล้ว ต้องดีพลอยใหม่ แล้วเรียก `setAudit` ผ่าน timelock

## สิ่งที่ยังขาด

- **ยังไม่ได้ดีพลอย**: `zetaphy deploy-audit` จะเขียนไฟล์ `deployments/audit-77390.json`
- **`audit/report.js`**: สร้างแยกต่างหาก ตัวต่อและ fixture กำหนดรูปแบบไว้แล้ว
- **ค่าตอบแทนกรรมการสำหรับข้อค้นพบหลังออกใบรับรอง**: ยังไม่มี
- **ยังไม่ผ่านการตรวจสอบ**: สัญญาเหล่านี้ยังไม่ได้ผ่านกระบวนการนี้เอง
