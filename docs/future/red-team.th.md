# Red team: เจาะให้เจอก่อนคนอื่น แล้วจ่ายให้คนที่เจาะได้

**ต้นแบบบนเทสต์เน็ต** ไม่มีอะไรที่นี่ถือหรือจ่ายเงินจริง การโจมตีทุกครั้งรันบน **fork ในเครื่องหรือ EVM ในหน่วยความจำ**
ไม่เคยรันบนเชนจริง เมนเน็ต หรือสัญญาของคนอื่น สัญญาเหล่านี้ยังไม่ผ่านการตรวจสอบ (audit)

การ audit บอกว่าสัญญาผ่านกระบวนการหนึ่งในวันหนึ่ง มันไม่ได้บอกว่าสัญญาเจาะไม่ได้ และไม่ได้พูดถึงเศรษฐศาสตร์รอบ ๆ มันเลย
Open Audit Network ([audit-network.th.md](audit-network.th.md)) คือทีมสีน้ำเงิน (blue team) ส่วนนี้คือ **ทีมสีแดง (red team)**:
ความพยายามต่อเนื่องที่จะเจาะสิ่งที่ได้ใบรับรองแล้ว ตลาดที่จ่ายเงินให้ใครก็ตามที่นำ exploit ที่ใช้งานได้จริงมา
และการจำลองที่ให้ตัวเลขว่าสัญญา DeFi เสียหายได้เท่าไรจากการโจมตีเชิงเศรษฐศาสตร์

สามส่วน แต่ละส่วนต่อยอดจากสิ่งที่เครือข่ายมีอยู่แล้ว (deterministic replay, ผู้รัน NeuroJobs ที่วางพันธบัตรพร้อม commit-reveal, CircuitBreaker):

| ส่วน | คืออะไร | อยู่ที่ |
|---|---|---|
| **S1 — ตลาด exploit** | ใครก็ส่ง exploit ที่ใช้ได้จริงต่อสัญญาที่ลงประกาศไว้ deterministic replay ตัดสิน ไม่มีกรรมการ ผู้ส่งได้เงินจาก escrow ของสัญญา และสัญญาอาจถูกหยุด | `zetaphy-network/contracts/ExploitMarket.sol` |
| **SS3 — AI red team** | เอเจนต์นอกเชนที่โจมตีสัญญาที่ได้ใบรับรองบน fork ในเครื่องไม่หยุด (คลังกลยุทธ์ + การค้นแบบสุ่มที่กำหนด seed, LLM ที่ไม่บังคับ) และสร้างคำร้อง S1 เมื่อเจอ exploit ที่ใช้ได้ | `zetaphy-network/src/redteam/…`, CLI `zetaphy redteam`, เวิร์กโฟลว์ `red-team` (รันเอง) |
| **SS4 — ความมั่นคงเชิงเศรษฐศาสตร์** | การจำลองการโจมตีเชิงเศรษฐศาสตร์ (sandwich, การปั่นออราเคิล, liquidation cascade) ต่อ DEX ให้ค่า "ความเสียหายสูงสุดที่ถอนได้ ≤ X" ที่ทำซ้ำได้ แนบเข้ากับคำขอ audit ได้ | `zetaphy-network/src/redteam/economic.js`, `zetaphy-network/contracts/EconomicBounds.sol` |

ส่วนที่เป็น deterministic ทั้งหมดทำงาน **โดยไม่ต้องมี API key หรือโมเดลใด ๆ** LLM เป็นเพียงแหล่งไอเดียการโจมตีที่ไม่บังคับ
และตัดสินผลลัพธ์ไม่ได้เด็ดขาด

## S1 — ตลาด exploit

ผู้สนับสนุนลงประกาศสัญญาบน ZETAPHY และวางเงินรางวัลไว้ใน escrow ใครก็ได้ (ยกเว้นผู้สนับสนุน) ส่ง exploit ที่ใช้ได้จริง:
ชุดธุรกรรมที่ replay บน **fork ของเชน** ที่บล็อกที่เลือก ผู้รัน NeuroJobs ที่วางพันธบัตรสามรายreplay ชุดนั้นและ commit คำตัดสิน
(commit-reveal ต้องตรง 2 ใน 3) ไม่มีกรรมการ — เพราะ replay เป็น deterministic ผู้รันที่ซื่อสัตย์สองคนจึงได้ไบต์เดียวกัน
exploit ที่ยืนยันแล้ว:

- จ่ายให้ผู้ส่งจาก escrow **ทันที** (ถอนแบบ pull) พร้อมพันธบัตรคืน;
- จ่ายส่วนแบ่งของรางวัลให้ผู้รันที่เห็นตรงกัน;
- ทำเครื่องหมายว่าประกาศนั้น **ถูกเจาะแล้ว** (ปิด; การแก้คือประกาศใหม่บนโค้ดใหม่);
- ถ้าสัญญาสมัครใช้ `CircuitBreaker` จะส่งอีเวนต์ `PauseRequested` พร้อมหลักฐานที่ผู้รันใช้ทริป breaker
  (องค์ประชุมและพันธบัตรของ breaker เองยังเป็นผู้ตัดสิน ส่วนนี้หยุดอะไรเองไม่ได้)

ประกาศหนึ่งกำหนดล่วงหน้าว่า exploit ที่ยืนยันแล้วจ่ายอะไร:

- คำร้องแบบ **loss**: replay ต้องแสดงว่า `asset` ที่ระบุ (เหรียญเนทีฟหรือ ERC-20) ออกจากเป้าหมายอย่างน้อยตามจำนวนที่อ้าง;
  รางวัลคือ `claimedLoss × unitValue × rewardBps` จำกัดที่ `maxReward` และยอด escrow;
- คำร้องแบบ **invariant**: replay ต้องทำให้ invariant หนึ่งในชุดที่ประกาศผูกไว้ (`invariantsHash`) เสียไป; รางวัลคือ `invariantReward` คงที่

**การผูกและกันลอก** `evidenceHash` ของคำร้องผูกเชน เป้าหมาย code hash ของมัน fork block แฮชของชุดธุรกรรม คำร้อง
**และ** ผู้ส่ง (ผู้รับเงิน) บนเชนมีแค่แฮช ส่วนชุดธุรกรรมส่งถึงผู้รันนอกเชน การลอกแฮชไม่ทำให้ใครได้เงิน ผู้รันที่เอาชุดของคนอื่นมาส่งเป็นของตัวเอง
จะอยู่หลังในคิวของประกาศ (มาก่อนได้ก่อน) พันธบัตรกันสแปมจ่ายให้ผู้รันเมื่อ exploit ถูกปฏิเสธ และคืนเมื่อไม่มีมติ 2 ใน 3

**ผลก่อนปฏิสัมพันธ์ (effects before interactions), ถอนแบบ pull** การเรียกเดียวที่ขยับมูลค่าคือ `withdraw`
ซึ่งตั้งยอดเครดิตเป็นศูนย์ก่อนจ่ายและไม่เขียนอะไรหลังจากนั้น ผู้สนับสนุนถอน escrow คืนได้ `unlistDelay` หลังจากขอ
(นานกว่าช่วงชีวิตทั้งหมดของคำร้องหนึ่ง) ไม่เคยถอนได้ขณะมีคำร้องค้างอยู่ ดังนั้นหนีจาก exploit ที่รู้แล้วไม่ได้
ธรรมาภิบาล (`ZetaphyTimelock`) ตั้งได้แค่พารามิเตอร์ที่มีขอบเขต ไม่เคยขยับ escrow ไม่มีกุญแจแอดมินใหม่

```
zetaphy exploit list   --market 0x… --target 0x… --pool 100 --min-loss 1 --unit-value 1 --max-reward 100 [--breaker --invariants suite.json]
zetaphy exploit submit --market 0x… --listing <id> --bundle redteam-0.json [--invariant <id> --suite suite.json]
zetaphy exploit commit --market 0x… --id <sub> --verdict report.json   # ผู้รัน; จากนั้น reveal แล้ว settle
zetaphy exploit withdraw --market 0x…
```

## SS3 — AI red team ตลอด 24 ชั่วโมง

เอเจนต์นอกเชน (`zetaphy-network/src/redteam/`) ที่ fork เชนในเครื่องและพยายามเจาะสัญญาไม่หยุด มันต้องใช้ ABI ของเป้าหมาย
(หาให้อัตโนมัติเมื่อโค้ดรันไทม์ตรงกับ artifact ใน repo)

**fork** (`fork.js`) คือ EVM ในหน่วยความจำ (EthereumJS ตัวเดียวกับที่เทสต์สัญญาใช้) ที่อ่านสถานะของเชนแบบ lazy ที่บล็อกเดียว —
ผ่าน JSON-RPC หรือเชนทดสอบของ repo เอง — และไม่เขียนกลับ; หรือ `anvil` ในเครื่องที่ผู้เรียกเปิดด้วย `--fork-url`
มัน **ปฏิเสธเชนที่ไม่ใช่เทสต์เน็ตหรือเชนในเครื่อง** (`TESTNET_CHAIN_IDS`): ชี้ไปที่เมนเน็ตไม่ได้ snapshot ซ้อนกันได้
การค้นจึงลองลำดับได้หลายพันแบบบน fork เดียว

**คลังกลยุทธ์** (`strategies.js`) แต่ละตัวอ่าน ABI และ fork แล้วเสนอแผนโจมตี:

- **access-control** — ฟังก์ชันที่ดูเหมือนมีสิทธิพิเศษถูกคนแปลกหน้าเรียก ทั้งเดี่ยว ๆ และตามด้วยการจ่ายเงิน;
- **reentrancy** — ฝากเงิน แล้วเรียกถอนที่ callback ของมันกลับเข้าไปซ้ำ 1..15 ครั้ง (ผ่านสัญญา `RedTeamAttacker` ของ red team);
- **flash-price** — flash-borrow โทเคน สวอปผ่านคู่ AMM ที่เป้าหมายใช้ตั้งราคา (ดันราคาสปอต) เรียกเป้าหมายด้วยทั้งหมดที่ซื้อได้ สวอปกลับและคืนเงินกู้ — การปั่นออราเคิล/ราคา;
- **signature-replay** — ส่งซ้ำการเรียกที่มีลายเซ็นซึ่งเห็นในประวัติของเป้าหมาย: ตามเดิม เปลี่ยนผู้รับเป็นผู้โจมตี หรือด้วย `s` ที่บิดได้ (malleable);
- **rounding** — จำนวนเล็ก ๆ หลายครั้งในธุรกรรมเดียว (การปัดที่เผา 0 share หรือจ่ายเกิน 1)

**การค้น** (`search.js`) เป็นการเดินสุ่มที่กำหนด seed เหนือลำดับการเรียก (จาก EOA หรือผ่านสัญญาโจมตี พร้อมการเข้าซ้ำ)
กลายพันธุ์จาก corpus ของลำดับที่ไปได้ไกลกว่า seed เดียวกัน fork เดียวกัน ผลเดียวกัน — ทำซ้ำได้
exploit ที่ใช้ได้ทุกตัวถูก **ย่อ (minimize)** ให้เหลือขั้นตอนน้อยที่สุดที่ยังทำสิ่งเดิมเสียได้

**LLM ที่ไม่บังคับ** (`agent.js`) ถามโมเดล (Ollama ในเครื่องโดยปริยาย หรือผู้ให้บริการใด ๆ ที่ตั้งผ่าน
`zetaphy-neuro/ai/providers.js` ซึ่งต้องมี API key) เอาแผนในภาษา JSON เล็ก ๆ ทุกแผนที่เสนอถูกตรวจกับ ABI และ
**รันบน fork เหมือนแผนอื่น ๆ** — โมเดลตัดสินผลไม่ได้ เสนอได้อย่างเดียว ถ้าไม่ตั้งโมเดล กลยุทธ์ deterministic และการค้นก็ทำงานลำพังและไม่มีอะไรเปลี่ยน

เมื่อ red team เจอ exploit ที่ใช้ได้ มันจะพิมพ์ออกมาและเขียน **ชุดคำร้อง S1** พร้อมสำหรับ `zetaphy exploit submit`

```
zetaphy redteam targets --certificate 0x<AuditCertificate>          # ทุกสัญญาที่มีใบรับรองที่ยังใช้ได้
zetaphy redteam scan    --target 0x… --source-rpc <testnet rpc> [--abi <artifact|file>] [--runs 300] [--out dir]
                        [--asset 0x… --min-loss <wei>] [--llm-model qwen2.5-coder:7b]
zetaphy redteam replay  --market 0x… --submission <id> --bundle bundle.json   # ผู้รันคำนวณคำตัดสินใหม่
```

**เวิร์กโฟลว์** (`.github/workflows/red-team.yml`) **ปิดโดยปริยาย**: รันเทสต์เมื่อ PR แตะ red team และผู้ดูแลรันการกวาดโจมตีเองได้
(`workflow_dispatch`) cron รายคืนถูกคอมเมนต์ไว้ ผู้ดูแลที่อยากได้ค่อยเปิดเอง มันรันบน fork ในเครื่องของเป้าหมายสาธิตเท่านั้น

### เป้าหมายสาธิตและเทสต์

`test/helpers/RedTeamDemo.sol` มีสัญญาที่ตั้งใจให้มีช่องโหว่หนึ่งตัวต่อหนึ่งประเภทบั๊ก — และ `SafeBank` ที่ไม่มีช่องโหว่
เพื่อให้ red team ต้อง **ไม่เจออะไร** กับมัน (ไม่ false positive) `test/redteam.test.js` รันแต่ละกลยุทธ์กับเป้าหมายของมัน
วง S1 ครบตั้งแต่ต้นจนจบ (ลงประกาศ → red team สร้างคำร้อง → ส่ง → ผู้รัน replay และยืนยัน → ผู้ส่งได้เงิน) การค้น และ hook LLM ด้วยผู้ให้บริการปลอม
`scripts/redteam-sweep.js` คือการกวาดแบบสแตนด์อโลนที่เวิร์กโฟลว์รัน

## SS4 — ความมั่นคงเชิงเศรษฐศาสตร์

การ audit ครอบคลุมโค้ด มันไม่ครอบคลุมว่าสัญญาเสียเท่าไรเมื่อตลาดรอบ ๆ มันถูกโจมตี SS4 (`economic.js`)
เป็นการจำลองการโจมตีเชิงเศรษฐศาสตร์ต่อ **ZETAPHY DEX** (สัญญา Factory/Pair/Router ของ `zetaphy-dex` จริง รันใน EVM ในหน่วยความจำ) ให้ค่า

> **ความเสียหายสูงสุดที่ถอนได้ภายใต้ชุดสถานการณ์ S ด้วย seed R ≤ X**

ทำซ้ำได้ทุกไบต์: สถานการณ์และ seed เดียวกันให้รายงานและตัวเลขเดียวกัน แต่ละสถานการณ์รันบนเชนในเครื่องใหม่ต่อ seed
โดยมีผู้เทรดสร้างสัญญาณรบกวนแบบกำหนด seed ขยับพูลก่อน:

- **sandwich** (MEV) — เหยื่อสวอปด้วยลิมิต slippage ผู้โจมตี front-run และ back-run กำไรของผู้โจมตีถูกจำกัดด้วยลิมิต slippage ของเหยื่อเอง (แสดงไว้)
- **oracle-spot** — ผู้ปล่อยกู้ที่ตีมูลค่าหลักประกันด้วยราคา **สปอต** ของคู่ ผู้โจมตี flash-borrow ดันราคาในธุรกรรมเดียว กู้ทับหลักประกันที่พองตัว แล้วเทกลับ ความเสียหาย = หนี้เสียของผู้ปล่อยกู้ *(ปั่นได้ — การจำลองแสดงความเสียหายมาก)*
- **oracle-twap** — ผู้ปล่อยกู้รายเดิมที่อ่าน **TWAP** ของคู่ตลอดช่วงเวลา การปั่นนับเฉพาะบล็อกที่ถือไว้ *(การจำลองแสดงว่ามันต้านการปั่นในบล็อกเดียวได้: ความเสียหาย 0)*
- **liquidation-cascade** — ผู้กู้ที่ใกล้เส้นชำระบัญชี ผู้โจมตีช็อกราคา ผู้ชำระบัญชีขายหลักประกันที่ยึดลงพูลเดียวกันและดันราคาต่อ ความเสียหาย = หนี้เสียที่เหลือหลัง cascade

ผู้ปล่อยกู้ ผู้กู้ และผู้ชำระบัญชีเป็นเอเจนต์ในการจำลอง (ยังไม่มีโปรโตคอลปล่อยกู้ใน repo) ทุกราคาที่พวกเขาเห็นและทุกการเทรดที่ทำคือ
**การเรียกจริงไปยังสัญญา DEX** บน fork

รายงานผูก **code hash** ของสัญญา DEX ที่จำลองและ **ชุดสถานการณ์ + seed** (`scenariosHash`) จึงทำซ้ำได้และตรวจการแก้ไขได้
`keccak256` ของมันคือค่าขอบเขตที่ผู้สนับสนุนแนบเข้ากับคำขอ audit:

```
zetaphy econ sim [--scenarios scenarios.json --seeds 1,2,3] [--out econ-report.json]
zetaphy econ attach  --bounds 0x<EconomicBounds> --request <id> --report econ-report.json --fee 1
zetaphy econ commit  --bounds 0x… --id <request> --report econ-report.json   # ผู้รันรันซ้ำและยืนยัน; จากนั้น reveal, settle
```

### `EconomicBounds` — แนบขอบเขตเข้ากับใบรับรอง

`EconomicBounds.sol` เป็นสัญญา **แยกต่างหาก**: มันไม่เปลี่ยนพฤติกรรมของ `AuditCertificate` ผู้สนับสนุนคำขอแนบ
`(reportHash, bound, scenariosHash)` ผู้รัน NeuroJobs ที่วางพันธบัตรสามราย **รันการจำลองซ้ำ** และยืนยันด้วย commit-reveal;
คำร้องยืนยันเมื่ออย่างน้อย 2 ใน 3 เปิดเผย `(reportHash, bound)` ที่ตรงกันเป๊ะ ผู้อ่านถาม `boundFor(chainId, target)`:
ขอบเขตใช้ได้ **เฉพาะ** ขณะใบรับรอง `AuditCertificate` ของเป้าหมายยังใช้ได้และออกให้คำขอที่ยืนยันขอบเขตนั้น
ดังนั้นขอบเขตอยู่นานกว่าใบรับรองที่มันอธิบายไม่ได้ และย้ายไปโค้ดอื่นไม่ได้ ผู้รันที่ยืนยันแบ่งค่าธรรมเนียมของผู้สนับสนุน
ไม่เช่นนั้นคืนให้ ถอนแบบ pull ไม่มีกุญแจแอดมิน

---

## สิ่งนี้คืออะไรและไม่ใช่อะไร

- exploit ที่ยืนยันแล้วพิสูจน์ **ความเสียหายนั้นบนโค้ดและสถานะนั้น** ด้วย replay มันไม่ใช่การพิสูจน์ว่าสัญญาไม่มีบั๊กอื่น
- ขอบเขตความเสียหายสูงสุดเป็นข้อความเกี่ยวกับ **สถานการณ์และ seed ที่จำลองเท่านั้น** ผู้โจมตีจริงมีสถานการณ์ที่ชุดนี้ไม่มี
  ขยายชุดและ seed สำหรับโค้ดสำคัญ ขอบเขตเป็นพื้นของสิ่งที่ผู้ป้องกันควรคาด ไม่ใช่เพดานของสิ่งที่ผู้โจมตีทำได้
- red team เจอบั๊ก **ประเภท** ที่กลยุทธ์และการค้นครอบคลุม การรันที่สะอาดเป็นหลักฐาน ไม่ใช่การรับประกัน
- ทุกอย่างอยู่บนเทสต์เน็ต ไม่มีเงินจริง ไม่มีเชนจริง ไม่มีกุญแจ fork ปฏิเสธเชนที่ไม่ใช่เทสต์เน็ตด้วย chain id ของมัน

## เศรษฐศาสตร์ (ค่าเริ่มต้น; ทุกค่ามีขอบเขต)

| พารามิเตอร์ | ค่าเริ่มต้น | ขอบเขต |
|---|---|---|
| พันธบัตรส่ง exploit | 1 ZTPHY | (0, 100] ZTPHY |
| ส่วนแบ่งของผู้รันจากรางวัล exploit (`runnerBps`) | 10% | 0..20% |
| หน้าต่าง commit / reveal (exploit) | 1 ชม. ต่ออัน | 1 ชม. .. 7 วัน |
| หน่วงถอนประกาศ (unlist) | 2×(commit+reveal) | ≥ 2×(commit+reveal), ≤ 90 วัน |
| องค์ประชุมผู้รันของขอบเขตเศรษฐศาสตร์ | 2 ใน 3 | คงที่ |
| หน้าต่าง commit / reveal ของขอบเขตเศรษฐศาสตร์ | 2 วันต่ออัน | คงที่ |

## สิ่งที่ยังขาด

- **ยังไม่ดีพลอย** `zetaphy deploy-redteam` ดีพลอย `ExploitMarket` (และ `EconomicBounds` เมื่อให้ที่อยู่ของ audit network และ certificate)
  บทบาทผู้รันใช้เกณฑ์ NeuroJobs เดิม
- **ยังไม่มีโปรโตคอลปล่อยกู้ใน repo** SS4 จึงให้ผู้ปล่อยกู้/ผู้กู้/ผู้ชำระบัญชีเป็นเอเจนต์ในการจำลอง ไม่ใช่สัญญาบนเชน เมื่อมีโปรโตคอลจริง สถานการณ์จะชี้ไปที่มัน
- **การหยุดบนเชน** จาก S1 คืออีเวนต์ `PauseRequested` พร้อมหลักฐาน การทริปจริงผ่านองค์ประชุมของ `CircuitBreaker` เอง (self-healing.th.md) S1 หยุดอะไรเองไม่ได้
- **ยังไม่ audit** สัญญาเหล่านี้ยังไม่ผ่าน Open Audit Network หรือกระบวนการอื่นใด
