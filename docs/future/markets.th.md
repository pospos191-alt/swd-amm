# พยากรณ์ ข้อมูล และตัวตรวจจับที่ใช้ฝึก Neuro (testnet)

ห้าส่วนที่เปลี่ยนวิจารณญาณของคนและโมเดลให้เป็นข้อมูลที่มีป้ายกำกับและตัวตรวจจับที่ดีขึ้นสำหรับ Neuro
**Testnet เท่านั้น** เงินวาง เงินประกัน และรางวัลทั้งหมดเป็น ZETAPHY ของ testnet ซึ่งไม่มีมูลค่า สคริปต์ปฏิเสธเชนอื่นนอกจาก 77390
ไม่ใช่ช่องทางหาเงิน และทุกที่ใช้คำว่า "พยากรณ์" ไม่ใช่ "พนัน" ไม่มีการแก้ `zetaphy-neuro/src/` (skill id ของ Neuro ไม่เปลี่ยน)

| # | รายการ | สถานะ |
|---|---|---|
| 15 | พยากรณ์ความเสี่ยง (RiskForecasts) + ส่งออกข้อมูล | **เสร็จ** (ต้นแบบ testnet มีเทสต์ ยังไม่ deploy) |
| 16 | Data DAO + การวัดผลงานข้อมูล + merkle root รางวัล | **เสร็จ** (ต้นแบบ ยังไม่ได้รันกับข้อมูลจริง) |
| 26 | ตัวตรวจจับที่วิวัฒน์ได้ (DetectorPool) + วงจรอัตโนมัติ | **เสร็จ** (ต้นแบบเทสต์เน็ต ผสมพันธุ์ → ส่ง → พยากรณ์ → เปิดเผย → ให้คะแนน → ปิดรอบ รันเป็นคำสั่งเดียวตามตาราง ทำซ้ำได้ มีเทสต์ ยังไม่ deploy) |

| 29 | Proof of Foresight (ForesightRegistry) | **เสร็จ** (มีเทสต์ ยังไม่ deploy) |

ภาพรวม: RiskForecasts (และสนามแข่ง) ตอบคำถามจากข้อเท็จจริงบนเชน → ForesightRegistry ให้คะแนน Brier ทุกคำพยากรณ์ที่ commit ไว้ →
DetectorPool จ่าย/หักเงินวางตัวตรวจจับตามคะแนน → งานกลายพันธุ์เพาะรุ่นใหม่จากตัวที่ดีที่สุด → คำถามที่ได้คำตอบและผลสนามแข่งถูกส่งออกเป็นข้อมูลฝึก →
Data DAO จ่ายรางวัลตามว่าข้อมูลช่วยโมเดลของ Neuro ได้แค่ไหน

## 29. Proof of Foresight
- model id (bytes32) เป็นของคนแรกที่ลงทะเบียน เปิดเหตุการณ์ได้เฉพาะ resolver ที่ governance อนุมัติ (สัญญาที่ตอบจากข้อเท็จจริงบนเชน)
- ก่อน `commitEnd` เจ้าของโมเดล commit `keccak256(eventId, modelId, p, salt)` (p เป็น basis points) หลังจากนั้นจึงเปิดเผย
  model id อยู่ในแฮช จึงลอก commitment ของคนอื่นไม่ได้ resolver ปิดการ commit ก่อนกำหนดได้
- คะแนน Brier `(p − ผลลัพธ์)²` เก็บบนเชน คำพยากรณ์ที่ไม่เปิดเผยนับเป็น 1.0 `skill` = ดีกว่าโยนเหรียญกี่ basis points (หดตาม n/(n+10))
- ใช้เป็นน้ำหนักใน DetectorPool และ `ml/detectors/spec.js foresightWeighted` (ให้คำแนะนำเท่านั้น ไม่ใช่คำตัดสิน)
- salt สร้างจากกุญแจ + เหตุการณ์ + โมเดล (`derivedSalt`) งานตามตารางจึง commit แล้วเปิดเผยทีหลังได้โดยไม่ต้องเก็บอะไร

## 15. พยากรณ์ความเสี่ยง
- คำถาม: LiquidityDrop (อีกฝั่งของพูลลดลง ≥ N% จากตอนเปิดคำถาม ก่อนกำหนด) หรือ Flagged (ถูกแจ้งเตือนใน ThreatRegistry ก่อนกำหนด)
- เลือกใช่/ไม่ใช่ด้วย ZETAPHY ของ testnet จนถึง `closeAt` และห้ามวางเมื่อเงื่อนไขเป็นจริงอยู่แล้ว
- คำตอบมาจากสถานะบนเชนเท่านั้น: ใครก็ `poke` ได้ การลดลงต้องคงอยู่ `confirmDelay` (1 ชม.) การแจ้งเตือนยืนยันทันที
  `propose` เสนอคำตอบ ช่วงโต้แย้ง 1 วัน (ประกัน 10) แล้ว governance ตัดสิน ผู้ทายถูกแบ่งเงินทั้งหมดตามสัดส่วน ถ้าไม่มีใครถูกหรือยกเลิก ทุกคนได้คืน
- ข้อมูลฝึก: `node scripts/markets.js export --forecasts 0x… --out forecasts.jsonl --votes votes.json` แล้วใช้ `ml/data/votes.js` อ่านเหรียญด้วย Neuro
- keeper รายชั่วโมงใน `.github/workflows/markets.yml` (เฉพาะเมื่อตั้งตัวแปร `RISK_FORECASTS` ส่งจริงเมื่อมี secret `MARKETS_KEY`)

## 16. Data DAO
- `submit(แฮช, uri, จำนวนแถว, สัญญาอนุญาต)` ไม่ซ้ำแฮช governance ตัดข้อมูลไม่ดีออกได้
- `ml/dao/attribute.js`: utility = −logloss บนชุดทดสอบที่ตรึงไว้ วิธี leave-one-contributor-out หรือ Shapley แบบสุ่ม
  ตัดแถวที่คนก่อนหน้าส่งแล้ว (ลอกมาได้ 0) ข้อมูลที่ไม่มีสัญญาอนุญาตแบบเปิดใช้ไม่ได้
- `markets.js dao-root` สร้าง merkle root, poster ที่ governance เลือกโพสต์รอบ, เคลมได้หลัง 2 วัน (ช่วง veto), หมดอายุ 60 วัน แล้ว `sweep` คืนพูล

## 26. ตัวตรวจจับที่วิวัฒน์ได้
- organism = spec ชุดกฎมีน้ำหนัก (`neuro-detector/1`) + เงินวาง + ต้นแบบ + specHash/URI + model id ใน Foresight (มีชีวิตได้สูงสุด 64)
- ทุกรอบ 7 วัน: Brier ดีกว่า 0.25 (อย่างน้อย 3 คำพยากรณ์) ได้รางวัลจากกองทุนและเงินที่ถูกหัก แย่กว่าถูกหัก 20% และนับ strike
  ครบ 3 strike หรือเงินวางต่ำกว่าขั้นต่ำถูกปลด ไม่พยากรณ์ 4 รอบติดถูกปลดโดยไม่หัก การขอออกมีผลหลังให้คะแนนรอบถัดไป
- `ml/detectors/mutate.js`: กลายพันธุ์ threshold/น้ำหนัก/ตัวดำเนินการ/เพิ่ม-ลบกฎ/ผสมพันธุ์ เก็บลูกเฉพาะที่ชนะพ่อแม่บนข้อมูลที่แยกไว้ 30%
- **วงจรอัตโนมัติ** (`zetaphy-network/src/detectorloop.js`, `node scripts/markets.js detectors-round` รันทุก 6 ชั่วโมงโดยงาน `detectors`
  ใน `markets.yml`) แต่ละรอบทำสิ่งที่ถึงกำหนด การรันซ้ำจึงปิดรอบได้โดยไม่ต้องทำมือ: (1) **ผสมพันธุ์** หนึ่งครั้งต่อรอบของ DetectorPool
  (seed คือเลขรอบ) เก็บลูกเฉพาะที่ Brier บน **ข้อมูลที่มีป้ายและแยกไว้** ดีกว่าพ่อแม่ (ไฟล์ที่คัดไว้ `--held` ถ้ามี ไม่งั้นแบ่ง 30% แบบคงที่)
  (2) **ส่ง**: model id ใน Foresight + organism พร้อมเงินวางทดสอบ ไฟล์ spec ตั้งชื่อตามแฮชและเผยแพร่บน branch `detectors/population`
  (3) **พยากรณ์** ทุกเหตุการณ์ Foresight ที่เปิดอยู่ของ RiskForecasts ด้วย feature ของเหรียญที่ Neuro อ่านจาก ZETAPHY salt คำนวณจากคีย์
  (4) **เปิดเผย** หลังปิดรับ: หา p จาก commitment บนเชนโดยลองครบ 10,001 ค่า จึงไม่ต้องเก็บอะไรระหว่างรอบ (5) **ให้คะแนน** เหตุการณ์ที่ตัดสินแล้ว
  (6) **ปิดรอบ** (`scoreRound`) เมื่อหมดเวลา ทุกรอบเขียน **manifest** (แฮชของข้อมูลเข้า seed พ่อแม่ ลูก ทุกคำทำนายพร้อม feature ที่ใช้ ทุกธุรกรรม)
  และ `checkManifest` คำนวณซ้ำแบบออฟไลน์ได้ ถ้าไม่มี `--send` (หรือ `DETECTORS_SUBMIT` ไม่ใช่ `on`) เป็นแค่แผน เฉพาะเทสต์เน็ต (77390)
- งาน `evolve` รายสัปดาห์ (ไม่ใช้คีย์) ยังผสมพันธุ์แบบออฟไลน์และอัปโหลดลูกเป็น artifact
- เทสต์: `test/detectorloop.test.js` (วงจรทั้งหมดด้วยธุรกรรมที่เซ็นจริงที่ chain id 77390 รันซ้ำแล้วไม่ทำซ้ำ อีกโลกหนึ่งได้ลูกและคำทำนายเหมือนกัน
  dry run ไม่ส่งอะไร และ CLI `detectors-round` ผ่านโหนด JSON-RPC) `ml/test/markets.test.js` (รวมชุดแยกที่คัดไว้)

## 27. แดงปะทะน้ำเงิน
- ทั้งสองฝั่ง commit ก่อน เปิดเผยทีหลัง runner (`ml/redteam/arena.js`) deploy เหรียญฝั่งแดงบน devnet ในหน่วยความจำเท่านั้น ให้ Neuro อ่าน
  แล้วจำลองเหยื่อซื้อ เจ้าของรันขั้นตอนกับดัก เหยื่อขาย: **ใช้ได้** เมื่อเหยื่อได้คืน < 50% **หลบได้** เมื่อใช้ได้และ Neuro แสดงต่ำกว่า medium
- ฝั่งน้ำเงินได้คะแนน = จับได้ − 2 × แจ้งเตือนเหรียญปกติผิด
- **ไม่ต้องไว้ใจ runner คนเดียว**: runner ที่ governance อนุมัติ **และ** วาง `runnerBond` (10 ZETAPHY ทดสอบ) รับที่นั่งได้สูงสุด `seats` (n ค่าเริ่ม 3)
  ด้วยการ commit `keccak(arena, round, runner, resultKey, salt)` ก่อน `resultCommitEnd` แล้วเปิดเผยผลเต็มก่อน `judgeEnd`
  **แซนด์บ็อกซ์ตรึงเวอร์ชัน**: รอบระบุ `sandbox` = แฮชของสภาพแวดล้อม (`ml/redteam/sandbox.js`: `@ethereumjs/evm` 3.1.1 / common 4.4.0 /
  util 9.1.0, solc 0.8.26, บล็อกคงที่, model id ของ Neuro, seed ของการจำลอง, ชุดเหรียญปกติอ้างอิง, เวอร์ชันกฎตัดสิน) และ `resultKey = keccak(sandbox, ผล)`
  runner ไม่ยอมตัดสินถ้าเวอร์ชันแพ็กเกจต่างหรือรอบเปิดด้วยแซนด์บ็อกซ์อื่น และการตัดสินสองครั้งได้ผลเหมือนกันทุกไบต์ (มีเทสต์)
  **finalize** (ใครก็ได้ หลัง `judgeEnd`): ผลที่ runner ครบ `quorum` (k > n/2) เปิดเผยตรงกันคือผลของรอบ runner ที่เปิดเผยผลอื่นหรือไม่เปิดเผยเสีย
  `slashBps` (50%) ของเงินประกัน ไม่ครบ quorum → โมฆะ (คนที่เงียบยังถูกหัก) **โต้แย้ง** (ใครก็ได้ ภายใน `challengeWindow` 1 วัน วาง `challengeBond`
  5 ZETAPHY ทดสอบ) ระบุผลที่ถูก governance (timelock) รันแซนด์บ็อกซ์ซ้ำแล้วตัดสิน: **ยอมรับ** → ใช้ผลของผู้โต้แย้ง runner ที่โพสต์ผลผิดถูกหัก ผู้โต้แย้งได้
  เงินคืนบวกครึ่งหนึ่งของที่หัก **ปฏิเสธ** → เงินวางไปให้ runner ที่ตรงกัน ไม่ตอบภายใน `appealWindow` (7 วัน) → หมดอายุ คืนเงิน ผลเดิมคงอยู่
  **settle** หลังหมดช่วงโต้แย้ง: จ่ายแดง/น้ำเงินเหมือนเดิม runner ที่ตรงกันแบ่ง `runnerFeeBps` (5%) ของกองรางวัลบวกเงินที่ถูกหัก
- คำสั่งของ runner (`scripts/markets.js`): `arena-fetch` → `node ml/redteam/arena.js --round round.json` → `arena-commit` → `arena-reveal` (salt
  คำนวณจากคีย์) → `arena-finalize` → `arena-check [--challenge]` → `arena-settle` และ `node ml/redteam/arena.js --sandbox` พิมพ์ sandbox id สำหรับเปิดรอบ
- เทสต์: `test/arena.test.js` (k-of-n การจ่าย quorum ที่สมรู้ถูกพลิกด้วยการโต้แย้ง การโต้แย้งที่ถูกปฏิเสธและหมดอายุ ไม่ครบ quorum เงินประกัน ที่นั่ง)
  `test/arena-runners.test.js` (runner สามคนผ่าน CLI จริง หนึ่งคนถูกหัก) `ml/test/arena.test.js` (sandbox id และการตัดสินที่เหมือนกันทุกไบต์)
- ผลส่งออกเป็น `dataset.jsonl` สำหรับฝึกโมเดล

## ข้อจำกัด (ตรงไปตรงมา)
- ยังไม่ deploy บน testnet
- ข้อเท็จจริงเรื่องสภาพคล่องยังถูกจัดฉากได้บ้าง (เพิ่มสภาพคล่องก่อนเปิดคำถามแล้วถอน) และมีช่วงรั่วระหว่างเหตุการณ์จริงกับการ poke ครั้งแรก
- Foresight มีอคติจากการเลือกเหตุการณ์ที่จะพยากรณ์ ยังไม่มีการบังคับให้พยากรณ์ทุกเหตุการณ์
- วงจรตัวตรวจจับเป็นอัตโนมัติครบแล้ว แต่ต้อง deploy สัญญาก่อน และตั้ง variable `DETECTOR_POOL`, `FORESIGHT`, `RISK_FORECASTS`,
  `DETECTORS_SUBMIT=on` และ secret `MARKETS_KEY` ใน environment `testnet-automation` ไฟล์ข้อมูลแยกที่คัดไว้ (`ml/detectors/held-out.jsonl`) ยังไม่มี
  จนกว่าจะคัด ลูกจะถูกตัดสินบน 30% ของข้อมูลสังเคราะห์ + red-team (ลูกที่ชนะที่นั่นอาจทำได้ไม่ดีกับเหรียญจริง คะแนน Foresight คือการทดสอบจริง)
- การวัดผลงานข้อมูลทดสอบกับข้อมูลสังเคราะห์เท่านั้น ชุดทดสอบจริงยังต้องคัดเลือก poster เป็นบทบาทที่ต้องไว้ใจ
- ไม่ต้องไว้ใจ runner คนเดียวแล้ว แต่ runner ยังต้องได้รับอนุมัติจาก governance และที่นั่งได้ก่อนได้ก่อน ผู้ดำเนินการคนเดียวที่มีหลายที่อยู่ที่ได้รับอนุมัติ
  และวางเงินประกันอาจครอง quorum ได้ ทางโต้แย้งเป็นด่านสุดท้ายและจบที่ governance (timelock) จึงต้องไว้ใจ governance ให้ตัดสินโต้แย้งอย่างซื่อตรง
  การตรวจ "ใช้ได้" ครอบคลุมกับดักที่ทำให้เหยื่อเสีย ≥ 50% ในไฟล์เดียว ไม่รวมการดูดเงินช้า ๆ หรือ phishing
- เทสต์ใช้ตัวแทนของ ThreatRegistry
