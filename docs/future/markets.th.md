# พยากรณ์ ข้อมูล และตัวตรวจจับที่ใช้ฝึก Neuro (testnet)

ห้าส่วนที่เปลี่ยนวิจารณญาณของคนและโมเดลให้เป็นข้อมูลที่มีป้ายกำกับและตัวตรวจจับที่ดีขึ้นสำหรับ Neuro
**Testnet เท่านั้น** เงินวาง เงินประกัน และรางวัลทั้งหมดเป็น ZETAPHY ของ testnet ซึ่งไม่มีมูลค่า สคริปต์ปฏิเสธเชนอื่นนอกจาก 77390
ไม่ใช่ช่องทางหาเงิน และทุกที่ใช้คำว่า "พยากรณ์" ไม่ใช่ "พนัน" ไม่มีการแก้ `zetaphy-neuro/src/` (skill id ของ Neuro ไม่เปลี่ยน)

| # | รายการ | สถานะ |
|---|---|---|
| 15 | พยากรณ์ความเสี่ยง (RiskForecasts) + ส่งออกข้อมูล | **เสร็จ** (ต้นแบบ testnet มีเทสต์ ยังไม่ deploy) |
| 16 | Data DAO + การวัดผลงานข้อมูล + merkle root รางวัล | **เสร็จ** (ต้นแบบ ยังไม่ได้รันกับข้อมูลจริง) |
| 26 | ตัวตรวจจับที่วิวัฒน์ได้ (DetectorPool) + งานกลายพันธุ์ตามตาราง | **เสร็จ** (ต้นแบบ วงจรพยากรณ์ของตัวตรวจจับยังกึ่งมือ) |
| 27 | สนามแดงปะทะน้ำเงิน (RedBlueArena) + runner ในแซนด์บ็อกซ์ | **เสร็จ** (ต้นแบบ runner ต้องเป็นที่ไว้ใจ) |
| 29 | Proof of Foresight (ForesightRegistry) | **เสร็จ** (มีเทสต์ ยังไม่ deploy) |

ภาพรวม: RiskForecasts (และสนามแข่ง) ตอบคำถามจากข้อเท็จจริงบนเชน → ForesightRegistry ให้คะแนน Brier ทุกคำพยากรณ์ที่ commit ไว้ →
DetectorPool จ่าย/หักเงินวางตัวตรวจจับตามคะแนน → งานกลายพันธุ์เพาะรุ่นใหม่จากตัวที่ดีที่สุด → คำถามที่ได้คำตอบและผลสนามแข่งถูกส่งออกเป็นข้อมูลฝึก →
Data DAO จ่ายรางวัลตามว่าข้อมูลช่วยโมเดลของ Neuro ได้แค่ไหน

## 29. Proof of Foresight
- model id (bytes32) เป็นของคนแรกที่ลงทะเบียน เปิดเหตุการณ์ได้เฉพาะ resolver ที่ governance อนุมัติ (สัญญาที่ตอบจากข้อเท็จจริงบนเชน)
- ก่อน `commitEnd` เจ้าของโมเดล commit `keccak256(eventId, modelId, p, salt)` (p เป็น basis points) หลังจากนั้นจึงเปิดเผย
  model id อยู่ในแฮช จึงลอก commitment ของคนอื่นไม่ได้ resolver ปิดการ commit ก่อนกำหนดได้
- คะแนน Brier `(p − ผลลัพธ์)²` เก็บบนเชน คำพยากรณ์ที่ไม่เปิดเผยนับเป็น 1.0 `skill` = ดีกว่าโยนเหรียญกี่ basis points (หดตาม n/(n+10))
- ใช้เป็นน้ำหนักใน DetectorPool และ `ml/detectors/spec.js foresightWeighted` (ให้คำแนะนำเท่านั้น ไม่ใช่คำตัดสิน)
- salt สร้างจากกุญแจ + เหตุการณ์ + โมเดล (`derivedSalt`) งานตามตารางจึง commit แล้วเปิดเผยทีหลังได้โดยไม่ต้องเก็บอะไร

## 15. พยากรณ์ความเสี่ยง
- คำถาม: LiquidityDrop (อีกฝั่งของพูลลดลง ≥ N% จากตอนเปิดคำถาม ก่อนกำหนด) หรือ Flagged (ถูกแจ้งเตือนใน ThreatRegistry ก่อนกำหนด)
- เลือกใช่/ไม่ใช่ด้วย ZETAPHY ของ testnet จนถึง `closeAt` และห้ามวางเมื่อเงื่อนไขเป็นจริงอยู่แล้ว
- คำตอบมาจากสถานะบนเชนเท่านั้น: ใครก็ `poke` ได้ การลดลงต้องคงอยู่ `confirmDelay` (1 ชม.) การแจ้งเตือนยืนยันทันที
  `propose` เสนอคำตอบ ช่วงโต้แย้ง 1 วัน (ประกัน 10) แล้ว governance ตัดสิน ผู้ทายถูกแบ่งเงินทั้งหมดตามสัดส่วน ถ้าไม่มีใครถูกหรือยกเลิก ทุกคนได้คืน
- ข้อมูลฝึก: `node scripts/markets.js export --forecasts 0x… --out forecasts.jsonl --votes votes.json` แล้วใช้ `ml/data/votes.js` อ่านเหรียญด้วย Neuro
- keeper รายชั่วโมงใน `.github/workflows/markets.yml` (เฉพาะเมื่อตั้งตัวแปร `RISK_FORECASTS` ส่งจริงเมื่อมี secret `MARKETS_KEY`)

## 16. Data DAO
- `submit(แฮช, uri, จำนวนแถว, สัญญาอนุญาต)` ไม่ซ้ำแฮช governance ตัดข้อมูลไม่ดีออกได้
- `ml/dao/attribute.js`: utility = −logloss บนชุดทดสอบที่ตรึงไว้ วิธี leave-one-contributor-out หรือ Shapley แบบสุ่ม
  ตัดแถวที่คนก่อนหน้าส่งแล้ว (ลอกมาได้ 0) ข้อมูลที่ไม่มีสัญญาอนุญาตแบบเปิดใช้ไม่ได้
- `markets.js dao-root` สร้าง merkle root, poster ที่ governance เลือกโพสต์รอบ, เคลมได้หลัง 2 วัน (ช่วง veto), หมดอายุ 60 วัน แล้ว `sweep` คืนพูล

## 26. ตัวตรวจจับที่วิวัฒน์ได้
- organism = spec ชุดกฎมีน้ำหนัก (`neuro-detector/1`) + เงินวาง + ต้นแบบ + specHash/URI + model id ใน Foresight (มีชีวิตได้สูงสุด 64)
- ทุกรอบ 7 วัน: Brier ดีกว่า 0.25 (อย่างน้อย 3 คำพยากรณ์) ได้รางวัลจากกองทุนและเงินที่ถูกหัก แย่กว่าถูกหัก 20% และนับ strike
  ครบ 3 strike หรือเงินวางต่ำกว่าขั้นต่ำถูกปลด ไม่พยากรณ์ 4 รอบติดถูกปลดโดยไม่หัก การขอออกมีผลหลังให้คะแนนรอบถัดไป
- `ml/detectors/mutate.js`: กลายพันธุ์ threshold/น้ำหนัก/ตัวดำเนินการ/เพิ่ม-ลบกฎ/ผสมพันธุ์ เก็บลูกเฉพาะที่ชนะพ่อแม่บนข้อมูลที่แยกไว้ 30%
- งานรายสัปดาห์ `evolve` และ `submit` (เมื่อ `DETECTORS_SUBMIT=on`) ใน `markets.yml`

## 27. แดงปะทะน้ำเงิน
- ทั้งสองฝั่ง commit ก่อน เปิดเผยทีหลัง runner (`ml/redteam/arena.js`) deploy เหรียญฝั่งแดงบน devnet ในหน่วยความจำเท่านั้น ให้ Neuro อ่าน
  แล้วจำลองเหยื่อซื้อ เจ้าของรันขั้นตอนกับดัก เหยื่อขาย: **ใช้ได้** เมื่อเหยื่อได้คืน < 50% **หลบได้** เมื่อใช้ได้และ Neuro แสดงต่ำกว่า medium
- ฝั่งน้ำเงินได้คะแนน = จับได้ − 2 × แจ้งเตือนเหรียญปกติผิด runner ตามจำนวน quorum ต้องโพสต์ผลตรงกัน สัญญาจ่ายรางวัลและคืน/ริบเงินประกัน
- ผลส่งออกเป็น `dataset.jsonl` สำหรับฝึกโมเดล

## หน้า hub
`zetaphy-hub/forecasts.html` (เมนู "พยากรณ์ความเสี่ยง") 8 ภาษา CSP เข้มงวด อ่านสัญญาจาก `hub-config.json` ถ้ายังไม่ deploy จะแสดงคำสั่งให้รันเอง

## ข้อจำกัด (ตรงไปตรงมา)
- ยังไม่ deploy บน testnet
- ข้อเท็จจริงเรื่องสภาพคล่องยังถูกจัดฉากได้บ้าง (เพิ่มสภาพคล่องก่อนเปิดคำถามแล้วถอน) และมีช่วงรั่วระหว่างเหตุการณ์จริงกับการ poke ครั้งแรก
- Foresight มีอคติจากการเลือกเหตุการณ์ที่จะพยากรณ์ ยังไม่มีการบังคับให้พยากรณ์ทุกเหตุการณ์
- วงจร "อ่านเหรียญ → ทำนาย → commit → เปิดเผย" ของตัวตรวจจับยังไม่มีงานตามตารางที่ต่อครบ
- การวัดผลงานข้อมูลทดสอบกับข้อมูลสังเคราะห์เท่านั้น ชุดทดสอบจริงยังต้องคัดเลือก poster เป็นบทบาทที่ต้องไว้ใจ
- runner ของสนามแข่งต้องไว้ใจ (quorum) การตรวจ "ใช้ได้" ครอบคลุมกับดักที่ทำให้เหยื่อเสีย ≥ 50% ในไฟล์เดียว ไม่รวมการดูดเงินช้า ๆ หรือ phishing
- เทสต์ใช้ตัวแทนของ ThreatRegistry
