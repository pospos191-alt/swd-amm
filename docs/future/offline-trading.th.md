# เทรดแบบออฟไลน์: เช็คที่เซ็นแล้ว และคำสั่งสวอปแบบออฟไลน์

**ใช้บนเทสต์เน็ตเท่านั้น** ไม่ใช่เงินจริง และสัญญายังไม่ผ่านการตรวจสอบความปลอดภัย (audit)

ฟีเจอร์นี้ทำให้จ่ายเงินและเทรดบน ZETAPHY ได้แม้ไม่มีอินเทอร์เน็ต ต้องใช้เน็ตแค่ตอนเริ่ม (ตั้งค่า) กับตอนจบ (ชำระบนเชน) ช่วงกลางทั้งหมดทำได้โดยไม่ต้องมีเน็ต ได้แก่ การเซ็น การส่ง QR หรือข้อความ และการตรวจ

| | ออนไลน์ครั้งแรก | ออฟไลน์ | กลับมาออนไลน์ |
|---|---|---|---|
| **เช็ค** (`ZetaphyCheques`) | ผู้จ่ายเปิดช่องทาง: วางเงินมัดจำ + กุญแจเซ็นเช็คแยกต่างหาก | ผู้จ่ายเซ็นเช็ค ผู้รับตรวจเช็ค | ผู้รับขึ้นเงินเช็คใบที่ดีที่สุด ผู้จ่ายถอนส่วนที่เหลือคืนหลังหมดอายุ |
| **คำสั่งสวอป** (`ZetaphyOfflineOrders`) | ผู้สร้างคำสั่งอนุมัติโทเคนให้สัญญาคำสั่ง | ผู้สร้างคำสั่งเซ็นคำสั่ง ใครก็ตรวจได้ | ใครก็ส่งคำสั่งขึ้นเชน (ทำสวอปบน ZETAPHY Swap) แล้วได้ค่าธรรมเนียม |

ในฮับ ทุกอย่างอยู่ที่แท็บ **ออฟไลน์** (`zetaphy-hub/offline.js`) ส่วนธนบัตรผู้ถือที่มีเงินค้ำซึ่งส่งต่อกันมือต่อมือ และเฟรมสำหรับ SMS / LoRa / คิวอาร์ อยู่ใน[เงินสดออฟไลน์และ Mesh](offline-cash.th.md)

## 1. เช็ค: ช่องทางจ่ายเงินทางเดียว

`zetaphy-network/contracts/ZetaphyCheques.sol`

- `open(payee, token, amount, expiry, signer)`
  - `token` เป็น 0 หมายถึง ZETAPHY เหรียญหลัก ส่งเป็น `msg.value`
  - `signer` คือกุญแจที่ใช้เซ็นเช็คของช่องทางนี้ เป็นกุญแจแยกต่างหาก ไม่ใช่กระเป๋าหลักของผู้จ่าย ฮับสร้างกุญแจนี้ในเบราว์เซอร์ให้
- `topUp(id, amount)` เติมเงิน และ `extend(id, expiry)` ยืดอายุ: ผู้จ่ายทำได้คนเดียว และต้องทำก่อนเริ่มปิดช่องทาง
- **เช็ค** คือข้อมูล EIP-712 `Cheque(uint256 channelId, uint256 cumulativeAmount)`
  - domain คือ `ZETAPHY Cheques` / `1` พร้อม chain id และที่อยู่สัญญา
  - ตัวเลขในเช็คคือ**ยอดรวมสะสม**ที่สัญญาว่าจะจ่ายให้ผู้รับ เช็คใบใหม่จึงใช้แทนใบเก่า
- `cash(id, cumulative, sig)` ขึ้นเงินเช็ค
  - ใครส่งก็ได้ แต่เงินเข้าผู้รับเสมอ
  - จ่าย `min(cumulative, deposit) − paid` คือไม่เกินเงินมัดจำเด็ดขาด
  - ถ้าภายหลังผู้จ่ายเติมเงิน เช็คใบเดิมขึ้นเงินส่วนที่เหลือได้
- `startClose(id)` เริ่มปิดช่องทาง: ผู้จ่ายทำได้ตั้งแต่ถึงวันหมดอายุ
  - จากนั้นเริ่ม**ช่วงคัดค้าน 24 ชั่วโมง** ระหว่างนั้นผู้รับยังขึ้นเงินได้
  - พ้นช่วงนี้แล้ว `withdraw(id)` คืนเงินที่เหลือให้ผู้จ่าย
- `release(id)`: ผู้รับยอมสละส่วนที่เหลือ ให้ผู้จ่ายถอนได้ทันที (ควรขึ้นเงินก่อน)
- ความปลอดภัย
  - ไม่มีเจ้าของ ไม่มีค่าธรรมเนียม ทุกฟังก์ชันกันการเรียกซ้อน (`nonReentrant`)
  - เปลี่ยนสถานะก่อนโอนเงินทุกครั้ง (CEI)
  - การเรียกโทเคน ERC-20 รับโทเคนที่ไม่คืนค่าอะไร แต่ปฏิเสธเมื่อคืน `false` เมื่อ revert หรือเมื่อที่อยู่ไม่มีโค้ด
  - **ปฏิเสธโทเคนที่หักค่าธรรมเนียมตอนโอน** โดยวัดยอดที่ได้รับจริง
  - ลายเซ็นต้องยาว 65 ไบต์ ค่า `s` ต้องต่ำ และ `v` ต้องเป็น 27/28 (รับ 0/1 ด้วย) จึงดัดแปลงลายเซ็นไม่ได้

### ผู้รับตรวจอะไรบ้างตอนออฟไลน์ (`verifyCheque` ใน `zetaphy-hub/offline-core.js`)

ผู้รับตรวจเทียบกับข้อมูลช่องทางที่ตัวเองอ่านจากเชนไว้ตอนซิงก์ล่าสุด ไม่เชื่อสิ่งที่เช็คอ้างเกี่ยวกับช่องทาง

เช็คจะผ่านเมื่อครบทุกข้อนี้:

- ลายเซ็นมาจาก `signer` ของช่องทาง
- chain id และสัญญาตรงกัน
- ยอดรวม**สูงกว่า**เช็คใบที่ดีที่สุดที่เครื่องนี้ถืออยู่ และสูงกว่ายอดที่ขึ้นเงินไปแล้ว
- ยอดใหม่บางส่วนอยู่ภายใน**เงินมัดจำ ณ ตอนซิงก์ล่าสุด**

หน้าเว็บแสดงเวลาซิงก์นั้น วันหมดอายุ และเวลาที่ต้องขึ้นเงินอย่างช้าที่สุด (หมดอายุ + 24 ชั่วโมง)

หน้าเว็บจะเตือนเมื่อ:

- ยอดเกินเงินมัดจำ
- ใกล้หมดอายุ (ไม่ถึงชั่วโมง) หรือหมดอายุแล้ว
- ซิงก์ไว้นานเกินหนึ่งวัน
- ช่องทางนี้จ่ายให้คนอื่น ไม่ใช่กระเป๋าที่เชื่อมต่ออยู่

## 2. คำสั่งสวอปแบบออฟไลน์

`zetaphy-network/contracts/ZetaphyOfflineOrders.sol`

- คำสั่งเป็นข้อมูล EIP-712 `Order{maker, tokenIn, tokenOut, amountIn, minAmountOut, deadline, nonce, relayerFee}` โดย domain คือ `ZETAPHY Offline Orders` / `1` พร้อม chain id และที่อยู่สัญญา
- `fill(order, sig, path)` ใครเรียกก็ได้ ทำตามลำดับนี้:
  1. ดึง `amountIn` พอดีจากผู้สร้างคำสั่ง ต้อง approve ไว้ก่อน หรือใช้ permit ตาม EIP-2612 ผ่าน `fillWithPermit` ส่วนโทเคนที่หักค่าธรรมเนียมตอนโอนจะถูกปฏิเสธ
  2. สวอปผ่านเราเตอร์ของ ZETAPHY Swap โดยตั้ง `amountOutMin = minAmountOut + relayerFee`
  3. จ่ายให้ผู้สร้างคำสั่งทั้งหมดยกเว้นค่าธรรมเนียม แล้วตรวจว่าผู้สร้างคำสั่งได้รับจริงอย่างน้อย `minAmountOut`
  4. จ่ายค่าธรรมเนียมให้คนเรียก
- ไม่มีการทำคำสั่งบางส่วน
- ผู้ส่งคำสั่งเลือกเส้นทางเองได้ (`path` ไม่เกิน 3 ทอด ถ้าว่างคือใช้พูลตรง) แต่ขั้นต่ำของผู้สร้างคำสั่งยังต้องได้ตามนั้น
- `tokenOut = 0` หมายถึงได้ ZETAPHY เป็นเหรียญหลัก (แกะออกจากเหรียญห่อให้)
- ถ้าจะ**ขาย** ZETAPHY เหรียญหลักแบบออฟไลน์ ให้ใช้เหรียญแบบห่อ บนเชน 77390 คือ ERC-20 ของเหรียญหลักที่ `0xEeee…EEeE` ในฮับแสดงเป็น `ZTPHY*`
- กันการใช้ซ้ำด้วย **nonce แบบบิตแมป** แยกตามผู้สร้างคำสั่ง ยกเลิกได้ด้วย `cancel(nonce)` หรือ `cancelWord(wordPos, mask)` และถ้าคำสั่งทำไม่สำเร็จ nonce จะยังไม่ถูกใช้
- ไม่มีเจ้าของ เราเตอร์กำหนดตายตัวตั้งแต่ตอน deploy

**ทำไมไม่ใช้ `IntentExecutor` ที่มีอยู่แล้ว** เราอ่านแล้วตัดสินใจไม่ใช้ เพราะ:

- intent แบบ SWAP บังคับให้ผู้ใช้เซ็นรายชื่อสัญญาที่ solver จะเรียก ผู้สร้างคำสั่งจึงต้องรู้เราเตอร์และแผนการเรียกตั้งแต่ตอนออฟไลน์
- ไม่มีค่าธรรมเนียมผู้ส่งที่หักจากผลลัพธ์
- nonce เป็น mapping ธรรมดา ไม่ใช่บิตแมป

สัญญาเล็ก ๆ ที่ทำงานเดียวและกำหนดเราเตอร์ไว้ตายตัว ตรวจสอบง่ายกว่าและเซ็นแบบออฟไลน์ได้ง่ายกว่า

## 3. แท็บออฟไลน์ในฮับ

- **กุญแจออฟไลน์**
  - เป็นกุญแจ secp256k1 ที่สร้างในเบราว์เซอร์
  - เก็บแบบ**เข้ารหัส**เท่านั้น: AES-GCM-256 ใช้กุญแจที่ได้จาก PBKDF2-SHA256 วน 600,000 รอบ (ตอนถอดรหัสต้องไม่ต่ำกว่า 310,000 รอบ)
  - ผูกที่อยู่ของกุญแจไว้กับข้อมูลที่เข้ารหัส (additional data ของ AES-GCM)
  - รหัสผ่านต้องยาวอย่างน้อย 10 ตัวอักษร
  - กุญแจที่ปลดล็อกแล้วอยู่ในหน่วยความจำเท่านั้น และล็อกเองหลัง 15 นาที
  - ส่งออกและนำเข้าไฟล์สำรองที่เข้ารหัสได้ การอ่านเขียนที่เก็บข้อมูลทุกครั้งอยู่ใน try/catch
- **QR**
  - วาดด้วย `zetaphy-hub/vendor/qrcode.js` คือ `qrcode-generator` 2.0.4 (สัญญาอนุญาต MIT) ตรึงค่า sha256 ไว้ใน `vendor/qrcode.json` และเสิร์ฟจากเว็บเราเอง ไม่ใช้ CDN
  - คัดลอกเป็นข้อความได้ (`ZCHQ1:` / `ZORD1:` ตามด้วย JSON แบบ base64url) หรือดาวน์โหลดเป็นไฟล์ `.txt`
- **การสแกน**
  - ถ้าเบราว์เซอร์มี `BarcodeDetector` เลือกรูปถ่าย QR ได้ (บนมือถือถ่ายด้วยกล้องได้เลย) ถ้าไม่มี ให้วางข้อความหรือเปิดไฟล์
  - ไม่มีไลบรารีถอดรหัส QR และไม่เปิดกล้องสด นโยบายสิทธิ์ `camera=()` ของเว็บจึงคงเดิม
- **ส่งคำสั่งขึ้นเชน**
  - ตรวจคำสั่งแบบออฟไลน์ก่อน
  - ตอนออนไลน์จะดูว่า nonce ยังไม่ถูกใช้ แล้วจำลองด้วย `eth_call` ของ `fill` ฟรี
  - กดส่งแล้ว ธุรกรรมจะออกจากกระเป๋าที่เชื่อมต่ออยู่ ผ่านหน้าสรุปก่อนเซ็นตามปกติของฮับ
- **Service worker** (`zetaphy-hub/sw.js`)
  - ลงทะเบียนเมื่อเปิดแท็บออฟไลน์ครั้งแรก
  - เก็บ**เฉพาะโครงหน้าเว็บแบบสถิต**: สคริปต์ สไตล์ ไอคอนของฮับ `hub-config.json` (ที่อยู่สาธารณะ) ตัวสร้าง QR และไฟล์รวมของกระเป๋า
  - `build.mjs` เขียนรายการไฟล์และแฮชของเวอร์ชันให้
  - ไม่เก็บคำขอแบบ POST ไม่เก็บข้อมูลจากเว็บอื่น (เช่น RPC) และไม่เก็บ `/api/`
  - ดึงจากเน็ตก่อนเสมอ ตอนออนไลน์จึงได้ไฟล์ล่าสุดทุกครั้ง
  - CSP เพิ่ม `worker-src 'self'` แล้ว
  - ตอนเบราว์เซอร์ออฟไลน์ แถบด้านบนจะขึ้นป้าย "ออฟไลน์"

## ภัยที่คิดไว้ และข้อจำกัด

| ความเสี่ยง | ใครเสี่ยง | อะไรป้องกันได้ / อะไรป้องกันไม่ได้ |
|---|---|---|
| ผู้จ่ายเซ็นเช็คเกินเงินมัดจำ | ผู้รับ | ผู้รับนับแค่ไม่เกินมัดจำ**ณ ตอนซิงก์ล่าสุด** และฮับไม่ยอมเซ็นเกินมัดจำ |
| ผู้จ่ายรีบปิดช่องทางหนีเช็ค | ผู้รับ | การปิดต้องถึงวันหมดอายุ**และ**ผ่านช่วง 24 ชั่วโมงที่ผู้รับยังขึ้นเงินได้ แต่ถ้าผู้รับออฟไลน์นานเกินหนึ่งวันหลังหมดอายุ อาจเสียเช็คที่ยังไม่ขึ้นเงิน **ควรขึ้นเงินก่อนหมดอายุ** |
| จ่ายซ้ำให้หลายคน | ผู้รับ | เป็นไปไม่ได้: ช่องทางหนึ่งมีผู้รับคนเดียวและมีเงินมัดจำของตัวเอง |
| ข้อมูลช่องทางเก่า | ผู้รับ | มัดจำไม่มีทางลดลงก่อนเริ่มปิด แต่ช่องทางอาจเริ่มปิดไปแล้วหลังซิงก์ หน้าเว็บจึงแสดงเวลา "ณ" และเตือนเมื่อเก่าเกินหนึ่งวัน |
| กุญแจออฟไลน์พร้อมรหัสผ่านถูกขโมย | ผู้จ่าย | คนร้ายเซ็นเช็คได้ไม่เกินมัดจำ และจ่ายได้แค่ผู้รับของช่องทางนั้น ควรใช้รหัสผ่านที่ยาวและไม่ซ้ำ และวางมัดจำแต่น้อย |
| ลืมรหัสผ่าน | ผู้จ่าย | เซ็นเช็คต่อไม่ได้ แต่มัดจำลบยอดที่ขึ้นเงินไปแล้วยังกลับมาหลังหมดอายุ + 24 ชั่วโมง |
| ข้อมูลในเบราว์เซอร์ถูกล้าง | ทั้งสองฝ่าย | ถ้าไม่ได้ส่งออกไฟล์สำรอง กุญแจจะหายไป ฝั่งผู้รับก็เสียเช็คที่ไม่ได้บันทึกไว้ ควรดาวน์โหลดไฟล์เช็คเก็บไว้ |
| ใช้กุญแจเดียวกันบนสองเครื่อง | ผู้จ่าย | แต่ละเครื่องนับยอดรวมของตัวเอง เช็คจากเครื่องที่ยอดตามหลังจะซ้ำกับยอดที่ผู้รับถืออยู่แล้ว ผู้รับจึงไม่รับ ("ไม่ใหม่กว่า") ไม่มีใครเสียเงิน แต่การจ่ายครั้งนั้นไม่สำเร็จ ควรเซ็นจากเครื่องเดียวในแต่ละช่วง |
| QR หรือข้อความที่มีเจตนาร้าย | ทั้งสองฝ่าย | อ่านอย่างเข้มงวด: จำกัดขนาด คำนำหน้าตายตัว ตรวจทุกช่องด้วย regex แสดงผลด้วย `textContent` และไม่รันอะไรเลย |
| คำสั่งถูกใช้ซ้ำ | ผู้สร้างคำสั่ง | nonce แบบบิตแมป และ domain ของ EIP-712 ผูกกับเชนและสัญญา |
| ผู้ส่งคำสั่งชิงทำก่อน หรือเลือกเส้นทางแย่ ๆ | ผู้สร้างคำสั่ง | สัญญาให้แค่ `minAmountOut` (หลังหักค่าธรรมเนียม) ซึ่งตรวจจากยอดที่ผู้สร้างคำสั่งได้รับจริง ตั้งค่านี้ให้ดี เพราะราคาตลาดอาจขยับระหว่างที่คำสั่งเดินทาง |
| คำสั่งที่ไม่ต้องการแล้ว | ผู้สร้างคำสั่ง | ยกเลิก nonce ตอนออนไลน์ ระหว่างนั้น**ใครถือข้อความไว้ก็ทำคำสั่งได้** |
| คำสั่งที่เซ็นด้วยกุญแจออฟไลน์ | ผู้สร้างคำสั่ง | มีแค่ที่อยู่ของกุญแจนั้นที่ยกเลิกได้ และฮับส่งธุรกรรมจากกุญแจนั้นไม่ได้ ควรเซ็นคำสั่งด้วยกระเป๋า |
| โทเคนหักค่าธรรมเนียมตอนโอน หรือโทเคนที่เรียกสัญญาซ้อน | ทุกคน | ปฏิเสธ (วัดยอดจริง) และใช้ `nonReentrant` ทดสอบกับโทเคนที่มีเจตนาร้ายแล้ว |
| บั๊กในสัญญา | ทุกคน | **ยังไม่ผ่าน audit ใช้บนเทสต์เน็ตเท่านั้น** |

## Deploy (เทสต์เน็ต)

```
cd zetaphy-network
ZETAPHY_RPC=https://… KEYFILE=./testnet-key.hex node scripts/offline-deploy.js [--router 0x…]
node scripts/offline-deploy.js check
```

`scripts/offline-deploy.js` (`src/offlinedeploy.js`) deploy สัญญาทั้งสองตัว

- ทั้งสองตัวไม่มีเจ้าของ กุญแจที่ใช้ deploy จึงไม่ได้ถือสิทธิ์อะไร
- ยอมทำบนเชน 77390 เท่านั้น
- เราเตอร์ใช้ของ ZETAPHY Swap จาก `zetaphy-dex/web/deployments.json` เป็นค่าเริ่มต้น
- ผลลัพธ์บันทึกที่ `zetaphy-network/deployments/offline-77390.json` ถ้ารันซ้ำจะทำต่อจากที่ค้างไว้

`zetaphy-hub/build.mjs` อ่านไฟล์นี้ พอ build ฮับรอบถัดไป แท็บออฟไลน์จะใช้ที่อยู่เหล่านี้ ก่อนหน้านั้นแท็บจะบอกว่ายังไม่ได้ deploy แต่การสร้างกุญแจออฟไลน์ การตรวจเช็ค และการเซ็นคำสั่งยังใช้ได้

## การทดสอบ

- `zetaphy-network/test/offline.test.js` ทดสอบสัญญาทั้งสองตัว
  - เส้นทางปกติ การใช้ซ้ำ ผู้เซ็นผิดคน ค่า `s` สูง ค่า `v` ผิด ช่องทาง สัญญา หรือเชนไม่ตรง
  - เช็คเกินเงินมัดจำแล้วเติมเงิน ช่วงคัดค้าน วันหมดอายุ release และ extend
  - การยกเลิกและ `cancelWord` เส้นตาย ขั้นต่ำที่ต้องได้ การรับเป็นเหรียญหลัก การขาย WZETAPHY และ permit
  - ปฏิเสธโทเคนที่หักค่าธรรมเนียมตอนโอน และกันการเรียกซ้อนทั้งผ่านโทเคนที่มี hook และผ่าน `receive()` ของผู้รับ

  ปิดท้ายด้วยการทดสอบตั้งแต่ต้นจนจบบน `rpcchain` ด้วยสัญญาของ DEX และธุรกรรมที่เซ็นจริง โดยใช้โค้ดของฮับเองทั้งการเข้ารหัสกุญแจ การเซ็น ข้อความที่ส่งต่อ และการตรวจ
- `zetaphy-hub/test/offline.test.mjs` ตรวจ
  - แฮช EIP-712 และ calldata เทียบกับ ethers
  - ลายเซ็นและการกู้ที่อยู่ผู้เซ็น การแปลงข้อความไปกลับ
  - การตรวจแบบออฟไลน์และกุญแจที่เข้ารหัส
  - ครบทั้ง 8 ภาษา และรายการไฟล์โครงหน้าเว็บ
- `zetaphy-hub/test/offline.e2e.mjs` ใช้ Playwright กับ CSP จริงของเว็บ หลังเข้าเว็บครั้งแรกจะสั่ง `context.setOffline(true)` แล้วโหลดหน้าใหม่ ฮับต้องขึ้นมาจาก service worker และแท็บออฟไลน์ยังทำสิ่งเหล่านี้ได้
  - ปลดล็อกกุญแจ และเซ็นเช็ค (QR และข้อความ)
  - ตรวจเช็คในฐานะผู้รับ: ใช้ได้ ต้องใหม่กว่าเท่านั้น และไม่เกินเงินมัดจำ
  - เซ็นและตรวจคำสั่งสวอป
