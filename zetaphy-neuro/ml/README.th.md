# Neuro ML: คะแนนความเสี่ยงที่เรียนรู้ได้ + ทีมจำลองผู้โจมตี (red team)

กฎตายตัวของ Neuro บอกว่าโค้ดของสัญญา **ทำอะไรได้บ้าง** โฟลเดอร์นี้เพิ่มสองอย่างไว้บนกฎเหล่านั้น ทั้งหมดฟรีและไม่มีเซิร์ฟเวอร์ที่เปิดตลอดเวลา:

- **ขั้นที่ 2 โมเดลที่เรียนรู้** (`model.json` ขนาด 75 KB): ต้นไม้ตัดสินใจแบบ gradient boosting ที่แปลงสิ่งที่ Neuro คำนวณอยู่แล้ว
  เป็นความน่าจะเป็น (ปรับเทียบแล้ว) ว่าโทเคนเป็นกับดัก พร้อมบอกว่าปัจจัยใดดันคะแนนขึ้นหรือลง
- **ขั้นที่ 5 red team** (`redteam/`): ดัดแปลงโทเคนหลอกลวงให้หลบ Neuro แล้วส่งผ่าน Neuro + โมเดล
  ทุกครั้งที่หลบได้จะถูกนำกลับไปเป็นข้อมูลฝึกและเป็นเทสต์กันถอยหลัง

การฝึกทำใน GitHub Actions สัปดาห์ละครั้ง (`.github/workflows/neuro-ml.yml`) และจะเสนอโมเดลใหม่ผ่าน pull request
เฉพาะเมื่อดีกว่าตัวปัจจุบันเท่านั้น ไม่มีการ deploy อัตโนมัติ

## กฎยังเป็นผู้ตัดสิน

- โมเดล **เพิ่ม** ระดับที่ Neuro แสดงได้ แต่ **ไม่มีทางลด** (`combine.js` ทดสอบทุกคู่ระดับและรายงานสุ่ม 600 รายการ)
- สัญญาของผู้ออกทางการหรือเทมเพลตที่ลงทะเบียน (กฎให้ "good") โมเดลเพิ่มได้สูงสุดแค่ "low"
- โมเดล **ไม่อยู่ใน verdict ของเครือข่ายและ reportHash**: `rulesLevel` คงเป็นสิ่งที่กฎตัดสิน ไม่เพิ่ม finding
  คะแนนอยู่ใน `analysis.ml` การตกลงกัน 2 ใน 3 ของ runner (src/verdict.js) ไม่เปลี่ยน
- `ml/` อยู่นอก `src/` จึงไม่เปลี่ยน skill id ของ Neuro (ไม่ต้องโหวต governance เพื่อใช้หรืออัปเดต)
- ถ้อยคำ: คะแนนเป็น "ค่าประมาณทางสถิติ" ไม่ใช่ข้อค้นพบ และไม่เรียกโครงการใดว่า "หลอกลวง"

## วิธีใช้

```js
import { checkModel } from './ml/model.js';
import { withModel } from './ml/combine.js';
const model = checkModel(await (await fetch('/ml/model.json')).json());   // ในเบราว์เซอร์ หรือ readFileSync ใน Node
const out = withModel(model, report, { code, logicCode, market, lang: 'th' });
// out.analysis.level      ระดับที่แสดง (>= ระดับจากกฎ)
// out.analysis.rulesLevel ระดับที่กฎตัดสิน (verdict ใช้ค่านี้)
// out.analysis.ml         { model, p, level, raised, top: [{feature, label, value, effect}] }
```

`node ml/cli.js bsc 0x...` ทำแบบเดียวกันกับโทเคนจริง (อ่านอย่างเดียวผ่าน RPC สาธารณะ) การประมวลผลเป็น JS ล้วนไม่มี dependency
(`model.js`, `features.js`, `combine.js`) หน้าเว็บ runner และ Node จึงได้ตัวเลขเดียวกัน

## โมเดล

Gradient-boosted decision trees (logistic loss, 160 ต้น ลึก 4, learning rate 0.15) เขียนเองทั้งหมดใน `train/gbdt.js`
แล้วปรับเทียบด้วย Platt บนชุดข้อมูลแยก การฝึกให้ผลเหมือนเดิมทุกครั้ง: เกณฑ์เรียงลำดับ, PRNG ที่มี seed, การตัดสินเสมอแบบตายตัว
และปัดทุกค่าเป็น 7 หลักนัยสำคัญ **ก่อน** ใช้ JSON ที่ส่งออกจึงให้คะแนนตรงกับตอนฝึกทุกบิต (`model.check` เก็บแถวที่เทสต์นำมาตรวจซ้ำ)
ทุกโหนดเก็บค่าของต้นไม้ย่อย คะแนนจึงแยกได้พอดีเป็น bias + ผลของแต่ละฟีเจอร์ (Saabas) นั่นคือ "เหตุผล" (`top`)
ทุกแถวถูกฝึกซ้ำอีกครั้งโดยตัดข้อมูลตลาดออก โมเดลจึงยังใช้ได้เมื่อไม่มีข้อมูลตลาด (กรณีปกติในเบราว์เซอร์)

ระดับที่โมเดลเพิ่มได้: low เมื่อ p >= 0.5, medium เมื่อ p >= 0.8, high เมื่อ p >= 0.95 (และต้องเข้มพอให้อัตราเตือนผิดในชุดปรับเทียบไม่เกิน 10% / 2% / 0.5%)

  สำหรับผู้ออกทางการหรือเทมเพลต) เพราะโมเดลที่เรียนรู้จับกับดักที่ไม่เคยเห็นไม่ได้ ไม่เพิ่มการเตือนผิดในชุดทดสอบ
- **เหตุผลเป็นภาษาคน** (`combine.js`): `ml.reasons` แสดงการตรวจที่พบ แล้วตามด้วยเฉพาะสิ่งที่ดันความเสี่ยงขึ้น

## Red team (`redteam/run.js`)

การดัดแปลง: เปลี่ยนชื่อฟังก์ชัน; `owner()` คืน 0 แต่ยังมีผู้ดูแลแฝง (แกล้งสละสิทธิ์); เก็บเจ้าของเป็นแฮช, เป็นตัวเลข XOR หรือตรวจผ่าน `tx.origin`;
ย้ายกับดักไปอีกสัญญา; proxy แบบกำหนดเองที่ไม่ใช่ EIP-1967; ห้ามขายหลัง N วัน (ระเบิดเวลา); ค่าธรรมเนียมขาย 99% หลัง N บล็อก;
กับดักที่ปล่อยให้การจำลองผ่าน (ราคา gas 0, origin ไม่มีเงิน, ผู้ขายเป็นสัญญา, ขาย 99% พอดี, gas เหลือมาก, coinbase 0)
ทุกแบบถูกคอมไพล์ deploy วางบน DEX และอ่านเหมือนชุดฝึก ไม่ต้องใช้ anvil/hardhat: เทสต์ของ Neuro ใช้ `@ethereumjs/evm` ในหน่วยความจำ ที่นี่ก็เช่นกัน

| รอบ | จำนวน | กฎ + การจำลองจับได้ | เมื่อเพิ่มโมเดล |
|---|---:|---:|---:|
| A กับโมเดลแรก (`data/redteam/report-A-vs-first-model.md`) | 160 | 51% | 58% (บันทึกที่หลบได้ 67) |
| B seed ใหม่ กับ `nml-b4c35477f7b1` (ฝึกจากที่หลบได้ในรอบ A) | 160 | 56% | 84% (หลบได้ 26) |
| B อีกครั้ง กับ `nml-3ab3cd303911` + การตรวจตามเส้นทาง (`report-B-fresh-vs-current.md`) | 160 | 56% | 97% (หลบได้ 5 ทั้งหมดเป็นกับดักเวลา/บล็อก/coinbase) |
| C seed ใหม่ กับ `nml-3ab3cd303911` + การตรวจตามเส้นทาง | 160 | 55% | 97% (หลบได้ 5) |

ข้อค้นพบ:
- โมเดลแรกพึ่ง "ยังมีเจ้าของ" มากเกินไป การซ่อนเจ้าของ (แกล้งสละสิทธิ์, แฮช, XOR, tx.origin) ดันคะแนนลง หลังเรียนจากรอบ A
  เจ้าของแบบแฮช/XOR/origin ถูกจับได้เป็นส่วนใหญ่ (B: 88% / 90% / 77%) แต่การแกล้งสละสิทธิ์ยังยาก (63%) เพราะ `owner() = 0`
  ดูเหมือนการสละสิทธิ์จริงทุกประการ
- ระเบิดเวลาและค่าธรรมเนียมตามบล็อกชนะการจำลองโดยการออกแบบ (กับดักยังไม่ทำงานตอน Neuro ซื้อขาย) โมเดลจับได้ 50% / 14% ในรอบ B
  โค้ด vesting ปกติก็ใช้ TIMESTAMP เวลาเพียงอย่างเดียวจึงไม่ใช่สัญญาณ
- การตรวจ "ผู้ขายเป็นสัญญา" (การจำลองขายจากสัญญา ผู้ใช้จริงขายจากกระเป๋า) ผ่านการจำลองได้ จับได้ 0 จาก 1 ในรอบ B
  ควรแก้ที่ `src/honeypot.js` (ขายจากที่อยู่ที่ไม่มีโค้ด) ไม่ใช่แค่ใน ML
- proxy แบบกำหนดเองซ่อนอินเทอร์เฟซโทเคนทั้งหมด แต่กฎ DELEGATECALL เตือนระดับ medium อยู่แล้ว (100%)
- ตัวอย่างที่หลบได้ 14 รายการที่โมเดลปัจจุบันยังพลาดอยู่ใน `data/redteam/known-gaps.json`;
  `ml/test/redteam.test.js` จะล้มเหลวถ้ารายการอื่นที่บันทึกไว้หลุดกลับต่ำกว่า medium

## ข้อจำกัด

## Federated learning (พร้อมบนเทสต์เน็ต ยังไม่ deploy; `fl/`)

เบราว์เซอร์ช่วยปรับคะแนนจากป้ายที่ผู้ใช้ยืนยันหลังรู้ผลได้ โดยไม่ส่งป้ายออกไป: หัว logistic regression ขนาดเล็กบนต้นไม้ที่ตรึงไว้
(`fl/head.js`, theta = 0 คือโมเดลนี้), การอัปเดตในเครื่องถูกตัดและใส่สัญญาณรบกวนก่อนออกจากอุปกรณ์ (local differential privacy,
epsilon 5.3 ต่อรอบที่ z = 2, งบ 16), commit-reveal บนเชนหรือซองที่ลงลายเซ็น, trimmed mean รายพิกัด, ด่านตรวจ canary และ trust region
โมเดล + หัวที่มีผลที่ความสูงบล็อกใดถูกเลือกโดย ModelEpochs บนเชน (`manifest.json` คือสิ่งที่บันทึก) รายละเอียด, การคำนวณความเป็นส่วนตัว,
การจำลองไคลเอนต์สุจริตกับไคลเอนต์วางยา และข้อจำกัด: [docs/future/federated.th.md](../../docs/future/federated.th.md) แผงในเบราว์เซอร์แบบเลือกเข้าร่วมอยู่ที่ `web/fl-panel.js` (ป้ายจากผู้ใช้และป้ายอัตโนมัติใน `fl/labels.js`) สัญญารอบยังไม่ deploy (`fl/deployment.json`)
